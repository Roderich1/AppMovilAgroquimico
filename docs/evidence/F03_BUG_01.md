# Evidencia F03-BUG-01 — un solo mensaje de estado de acceso en el Dashboard

Issue [#83](https://github.com/Roderich1/AppMovilAgroquimico/issues/83). Ejecución automatizada con Claude Code el 2026-10-15/16 (America/La_Paz), en host Windows 11 con Flutter 3.47.2. Sin dispositivo.

## Defecto

En el POCO, durante el caso D de #71 (2026-10-15, 21:22), el Dashboard mostraba a la vez dos mensajes:
- el estado de **arranque**, «Cuenta vinculada en este dispositivo. El estado en línea aún no fue verificado.» (`ExistingSessionStartupState.safeMessage`), que no cambia;
- el estado **remoto** vigente, «Acceso en línea verificado para esta sesión.» (`RemoteSessionState.safeMessage`).

Al reabrir con el guard en cuarentena pasaba algo parecido: «aún no fue verificado» y «El acceso en línea todavía no se verificó.» aparecían junto al botón «Volver a autenticar». La captura `71-D-02-despues.png` tiene SHA-256 `80729db9…5d26` y está en `docs/evidence/F03_RES_01_DEVICE.md`.

## Corrección

`lib/presentation/screens/dashboard_screen.dart`:
- Con sesión local (`localSessionAvailable` o `localSessionExpired`) hay **un solo** texto de estado (`Key('local-session-status')`). Lo calcula la función pura `sessionStatusMessage`:
  - si hubo actividad remota en este proceso, muestra el mensaje remoto;
  - si no, y el guard está en cuarentena, muestra «Se requiere volver a autenticar…»;
  - si la lectura del guard falló, muestra el mensaje de guard no disponible;
  - en otro caso, el mensaje de arranque.
- `_RemoteSessionControls` ya no pinta su propio mensaje.
- Sin cambios en el coordinador de refresh, el guard, el almacenamiento seguro ni las acciones: los botones «Verificar acceso en línea» y «Volver a autenticar» siguen igual.
